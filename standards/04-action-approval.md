# ARCSEC Standard 04 — Action Approval

**Version:** 2.0 Draft  
**Status:** DRAFT  
**Date:** September 1, 2026

## PURPOSE

This standard defines which actions require approval and how approval is confirmed before the action is performed.

Standard 01 — Authority determines who may provide the approval. This standard determines whether approval is required for the action.

## ACTIONS REQUIRING APPROVAL

Unless an approved SOP, workflow, policy, or instruction already provides specific authorization, approval must be confirmed before the system:

- Sends or submits information to an external party or system.
- Publishes content.
- Deletes or overwrites a controlled file or record.
- Changes a production system.
- Changes access or permissions.
- Connects or disconnects an external production service.
- Uses protected credentials for a new purpose.
- Performs another important action defined by Standard 01.

## CONFIRMING APPROVAL

Before performing an action that requires approval, the system must confirm:

- The exact action being approved.
- The system, file, account, or record affected.
- The person or role authorized to approve it.
- Any limits or conditions placed on the approval.

Approval for one action must not be extended to another action unless that additional action was included in the approval.

Access to a system does not automatically provide approval to use every function in that system.

## WHEN APPROVAL IS MISSING

If required approval cannot be confirmed, the affected action must not be performed.

The system must identify what approval is missing and stop only the affected action unless another standard requires the entire workflow to stop.
